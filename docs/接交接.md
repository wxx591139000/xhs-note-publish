### 它是什么

把 AI 融入日常工作的**辅助发布**工具：电脑端统一管理素材（标题/正文/标签/封面/多图），手机端打开固定网址一键复制文案，粘到 APP 里人工发布。

**核心理念：小红书有风控，不做 API 自动发布。** 工具只负责「素材组织好 + 一键复制 + 自动填草稿」，发布动作由人在 APP 内完成，最稳。闲鱼同理。

### ★ v1.6.1 这次修的是什么（本档最容易复发的点）

**症状**：打开 `/app`，左侧「笔记队列」**51 张缩略图全是灰占位图**。

**根因**：`static/app.js` 渲染列表缩略图那行 `src="${n.images[0] || '/static/placeholder.png'}"` ——
而 **`/api/notes` 返回的 `images` 是「裸哈希文件名」**（不含路径），直接当 `src` 用 → **404**。
该 `<img>` 又带 `onerror` 兜底自动换占位图 ⇒ **页面"看着有图"，肉眼察觉不到**。

**为什么长期没被发现**：手机端 `mobile.js`（4 处）与桌面端**预览面板 + 缩略图网格**（5 处）**前缀全都写对了** —— **只有列表这一处漏了**。

**实测证据**：修复前缩略图 `src` 取值种类 = **1**、图片请求 **≥400 共 32 个且 32/32 均为「缺前缀」**、`/uploads/` 下 404 = **0**；
修复后 `src` 种类 **1→33**、真图加载 **0→32**、图片 404 **32→0**。

⇒ ★ **一般化判据**：同一份数据被 N 处渲染时，**把这 N 处的同一表达式 grep 出来并排看**；
**核验必须下沉到网络状态码 / 像素**（"元素存在"≠"用户看得见"）。

## 三、架构要点（一句话版）

```
电脑/手机浏览器 ──→ Flask app.py (0.0.0.0:8800) ──→ SQLite data/notes.db
                        │
                        ├─ templates/ desktop / mobile / login / send
                        ├─ static/ app.js · mobile.js · send.js · style.css
                        └─ CORS 白名单（纵横工作台 / xhs 域名 / file://）
                     ↑
        本机 cloudflared 隧道 xhs-tunnel → https://xhs.zhuanlu.xyz
```

- **排序是前端行为**：`/api/notes` 与 `/api/auto/notes`（AutoX.js 按 `position` 自动发布）**顺序必须保持原样**，改动后端排序会静默改变自动发布顺序。
- **`sortNotes()` 与 `stripImgSlots()` 在 `app.js` / `mobile.js` 各有一份** → 必须双端一致，由两个回归脚本守（48 组 / 14 组矩阵断言）。
- **图位标记（双中括号包图号）是内部语法**：所有出站路径（复制文案 / 卡片显示 / 字数统计）必须先 `stripImgSlots()`，否则会漏到发布文案里。语法与示例见 `E:\myClaudCodeWorkspace\xhs-note-publish\docs\PITFALLS.md`。
- ★ **图片路径由渲染层拼**：`/api/notes` 的 `images`/`cover` 是**裸文件名**，**每一处渲染都得自己拼 `/uploads/` 前缀**（全项目共 10 处：桌面 6 处 + 手机 4 处）。清单见 `E:\myClaudCodeWorkspace\xhs-note-publish\docs\ARCHITECTURE.md` 的「图片渲染链路」小节。
