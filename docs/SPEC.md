# 小红书笔记发布工具 · 项目目标 SPEC

> 版本：v1.3.0（2026-08-21 归档）

## 项目定位

把 AI 融入日常工作——电脑端统一管理小红书笔记素材，手机端「辅助发布」到小红书 APP。参考生财有术文章《把 AI 融入日常工作，随手做出一个小红书笔记发布工具》。

**核心理念**：小红书有风控，**不做 API 自动发布**。工具负责把素材组织好、一键复制、自动填草稿，发布动作由用户在小红书 APP 内完成，最稳。

## 技术栈与架构概览

- **后端**：Python Flask 3.x + SQLite（`sqlite3` 标准库，无 ORM）
- **前端**：原生 HTML/CSS/JS，**无外部 CDN 依赖**（内网/隧道可离线用）
- **二维码**：Python `qrcode`
- **自动化**：AutoX.js（安卓无障碍服务）
- **部署**：本地 Windows 跑 Flask + cloudflared 新隧道 `xhs-tunnel`（27da88b4）

## 关键接口

- 页面：`/login`、`/app`（桌面）、`/m`（手机）
- 笔记：`GET/POST /api/notes`、`PUT/DELETE /api/notes/<id>`、`POST /api/notes/<id>/publish|revert`
- 上传：`POST /api/upload`、静态 `GET /uploads/<file>`
- 设置：`PUT /api/settings`（密码）
- 自动化：`GET/POST /api/auto/token`、`GET /api/auto/notes?token=`、`POST /api/auto/notes/<id>/drafted?token=`、`GET /xhs_auto.js`
- 二维码：`GET /api/qr`

## 已知约束与边界

- 图片进小红书必须「先存相册再选」，浏览器无法把多图粘进小红书（平台硬限制）
- 手机浏览器**批量下载会被拦截/弹窗闪烁**，图片下载必须「逐张确认」（用户亲手触发）才稳定
- 手机浏览器会**缓存静态 JS**，改代码后需带版本号强制刷新，否则旧逻辑不生效
- iOS 无无障碍自动化，自动填充仅安卓可用
- 小红书 UI 改版会导致 AutoX.js 选择器失效，需按版本微调
- 闲鱼（淘宝系）自动发布风控更严，仅手动复制 + 用途标记，不做 API 自动发布
- 自动操作有被小红书设备指纹识别风险，建议低频率 + 存草稿人工审核
- 素材和 DB 存本机，电脑关机/隧道断开时手机无法访问
