# 小红书笔记发布工具 · 项目踩坑记录

> 版本：v1.2.0（2026-08-21 归档）

## 踩坑清单

### [2026-08-18] start.bat 用旧 transcribe-bot 隧道会抢 VPS 隧道
- **问题**：`start.bat` 隧道命令写的是 `cloudflared tunnel run transcribe-bot`，一旦双击会抢 VPS 转录 bot 的隧道，导致 `upload.zhuanlu.xyz` 等域名 502
- **原因**：双隧道拆分后（`COORDINATION.md`）本地小红书应走 `xhs-tunnel`(27da88b4)，但 start.bat 没跟着改
- **解决/规避**：改为 `cd /d C:\Users\Dancing\.cloudflared && cloudflared tunnel run xhs-tunnel`（必须 cd 到 .cloudflared 目录，cloudflared 才自动加载 config.yml）

### [2026-08-14] Windows curl 中文 JSON 返回 400
- **问题**：用 curl `-d '{"title":"中文"}'` 创建笔记报 400 Bad Request
- **原因**：Windows Git Bash 下命令行中的中文 JSON 被 shell 编码破坏，Flask 解析失败
- **解决/规避**：改用 `--data-binary @file.json`（JSON 写入 UTF-8 文件），或直接用 `import_note.py`

### [2026-08-14] 产线稿子标签抓空
- **问题**：导入脚本标签为空
- **原因**：标签行(`#打工人 #AI工具...`)在正文的 `---` 分隔之后，不在正文里；且正则 `^[#＃]` 会误匹配 markdown H1 标题行
- **解决/规避**：标签改为在**全文** hunt，且用 `^[#＃]\S+(?:\s+[#＃]\S+)+$`（要求一行全是 #tag 才认）

### [2026-08-14] 正文开头混入 H1 标题
- **问题**：导入后正文含 `# 🤩标题` 行
- **原因**：frontmatter 去掉后正文以空行开头，`while` 循环没跳过空行，导致 H1 没被剔除
- **解决/规避**：循环条件加 `not body_lines[0].strip()`（先跳空行再跳 H1）

### [2026-08-14] 产线图片引用的 `|500` 尺寸后缀
- **问题**：`![[images/xxx.png|500]]` 直接当路径找不到文件
- **原因**：Obsidian 嵌入语法带 `|尺寸` 后缀
- **解决/规避**：解析时 `split("|")[0]` 去掉后缀

### [2026-08-14] 部分稿子 impc 正文没嵌图但 images 目录有图
- **问题**：10 篇稿子导入后无图
- **原因**：产线稿子 markdown 未写 `![[images/...]]` 引用，但 images 目录里其实有同名图
- **解决/规避**：导入脚本加「标题前缀匹配 images 目录」兜底逻辑

### [2026-08-14] 误把 xhs 加进旧隧道抢 VPS（关键）
- **问题**：本会话把 `xhs.zhuanlu.xyz` 加进旧 transcribe-bot 隧道(1779cc80)并启动 `cloudflared tunnel run transcribe-bot`，会抢 VPS 隧道致 upload.zhuanlu.xyz 502
- **原因**：隧道未拆分时误用旧配置
- **解决/规避**：已拆分为双隧道——VPS(1779cc80)管 transcribe/kf/upload，本地 xhs-tunnel(27da88b4)只管 xhs。**严禁用旧配置重启本地 cloudflared**。详见记忆 `cloudflared-two-tunnel-convention`

### [2026-08-14] AutoX.js 选图/按钮依赖小红书 UI 版本
- **问题**：小红书改版会导致选择器失效
- **原因**：无障碍自动化基于文案/控件 id，UI 变动即失效
- **解决/规避**：脚本内做多文案候选 `clickText(["相册","图片",...])`，并留坐标兜底；真机 DRY_RUN 后按日志微调

### [2026-08-14] 手机浏览器批量下载被拦截/弹窗闪烁
- **问题**：点「下载全部图」一次触 3 次下载，页面快速闪过多个下载界面、漏图
- **原因**：手机浏览器安全机制——单个用户手势只允许触发一次下载，后续自动下载被拦截或弹窗堆叠
- **解决/规避**：改为「逐张确认」——每张由用户亲手点「保存此图」触发（新鲜手势），点完按钮变「下一张」，全程用户控制节奏，绝不自动跳

### [2026-08-14] 手机浏览器缓存旧 JS，改了没变化
- **问题**：用户改完 mobile.js 后手机端仍显示旧行为（「没变化」）
- **原因**：手机浏览器强缓存静态 JS，旧逻辑还在跑
- **解决/规避**：模板引用加版本号 `?v=20260814-3`，URL 变化即重新拉取；并引导用户强制刷新

### [2026-08-14] AI产线图「看着像重复」
- **问题**：用户以为一篇笔记的 3 张图有重复（保存时提示像一样）
- **原因**：AI 生成的插图风格统一、主题相近，视觉上像同一张，但 MD5/像素/dHash 三重比对均不同
- **解决/规避**：非 bug。下载文件名只有尾号不同易误判，可改名区分或换差异大的图

### [2026-08-21] 手机端 `.m-filters` 选择器会同时选中平台筛选 chips
- **问题**：状态筛选绑定 `document.querySelectorAll('.m-filters .chip')`，平台组父容器也带 `.m-filters` 类 → 平台 chips 被状态 handler 误绑，点平台出怪
- **原因**：新增平台筛选时复用了 `.m-filters` 容器类
- **解决/规避**：状态组容器加独立 `id="mStatusFilters"`，绑定限定 `#mStatusFilters .chip`；平台组用 `#mPlatFilters .chip`

### [2026-08-21] 闲鱼与小红书共用队列，需用途标记防点混
- **问题**：同一队列同时发小红书+闲鱼，全默认「通用」时两个发布按钮都在，易误点
- **原因**：无平台维度区分，靠人记
- **解决/规避**：加 `meta.purpose`（xhs/idlefish/common）；桌面徽标、手机端平台筛选、按钮按用途收敛（闲鱼稿只显示宝贝按钮、小红书稿只显示复制文案）

## 已知风险（非 bug，业务约束）
- 小红书图片只能「先存相册再选」，浏览器无法多图粘进小红书
- 自动化有设备指纹识别/封号风险，建议低频率 + 存草稿
- iOS 无无障碍自动化，自动填充仅安卓
