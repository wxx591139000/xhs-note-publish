# 小红书笔记发布工具 · 项目踩坑记录

> 版本：v1.6.1（2026-10-01 二次归档）

## 踩坑清单

### [2026-10-01] ★★ 桌面列表缩略图全不可见 —— 拼图路径只有这一处漏了 `/uploads/` 前缀
- **问题**：打开 `/app`，左侧「笔记队列」**51 张缩略图全部是灰占位图**；但**同一批笔记**在手机端 `/m`、以及桌面端**右侧预览面板**里图全都正常
- **原因**：`static/app.js` 渲染列表缩略图那行写成
  `src="${n.images[0] || '/static/placeholder.png'}"` —— 而 **API 返回的 `images` 是「裸哈希文件名」**（不含路径），直接当 `src` 用 → 请求 `/85d99dd….png` → **404**
  同文件另外 5 处（缩略图网格 / 封面 / 预览封面 / 正文配图 / 末尾兜底）与 `mobile.js` 4 处**全都写了 `/uploads/${f}`** —— **孤立一处漏拼**
- **解决/规避**：改为 `src="${n.images[0] ? '/uploads/' + n.images[0] : '/static/placeholder.png'}"`
- **实测证据**：修复前缩略图 `src` 取值种类 = **1**（全占位图）、浏览器图片请求 **≥400 共 32 个且 32/32 都是「缺前缀」**、`/uploads/` 下 404 = **0**；修复后 `src` 种类 **1→33**、真图加载 **0→32**、图片 404 **32→0**
- ⚠️ **`onerror` 兜底会把缺陷伪装成正常**：该 `<img>` 带 `onerror="this.src='/static/placeholder.png'"`，页面**看起来"有图"**、`<img>` 元素计数也正常 ⇒ **肉眼与元素计数都判不出来**，判据必须下沉到**像素 / 网络状态码**
- ⚠️ **先排除"加载等待不足"这个替代解释**：`loading=lazy` → 改 `eager` + 滚动全程 + 等所有 `img.complete`，**仍全占位** ⇒ 才能断定是 **code bug 而非时序问题**
- ★ **一般化判据**：同一份数据被 **N 个地方**渲染时，把 **N 处的同一表达式 grep 出来并排看** —— 任何一处长得不一样就是嫌疑（**数据同源 ≠ 渲染同实现**）
- 断言见 `tools/verify_preview_render.mjs`（渲染 + 网络判据）、`tools/verify_pixel_proof.mjs`（像素判据）

### [2026-10-01] ★★ 校验脚本自己写错字段名 —— 32 张「加载成功」的真图被全判为坏图
- **问题**：写缺陷取证脚本时，输出出现自相矛盾的行：`BAD nw=2400 complete=true`（判为"坏图"却有宽 2400）
- **原因**：`page.$$eval` 的 map 里字段命名为 **`nw`**，而下游 filter 写的是 **`t.naturalWidth`** ⇒ `undefined > 1 = false` ⇒ **全部误判为 BAD**
- **解决/规避**：统一字段名，并**就地写注释警告**（`// ★ 注意：字段名是 nw，不是 naturalWidth —— 写错会静默全判 BAD`）
- ★ **教训**：这是「**同一件事两个判据/两份实现 → 结论相反**」的又一实例。**统计类判据里字段名不一致 = 判据静默恒假**，且不会报错，只会给出一个"看起来很确定"的错误结论
- ★ **可复用的自检**：判据输出**自相矛盾**时（如"坏图"却有正常尺寸），**先怀疑判据而不是被观测对象**

### [2026-10-01] Flask 静态文件 vs 模板缓存的**行为差异**（实测澄清）
- **问题**：改了 `templates/desktop.html` 里的 `app.js?v=` 版本号，直接请求 `/app` 发现**版本号仍是旧值**，一度以为改动没生效
- **实测结论**：
  | 对象 | `debug=False` 下行为 | 后果 |
  |---|---|---|
  | **静态文件** `/static/app.js` | **每次从磁盘读**（`Last-Modified` 即时更新） | 改完**刷新即生效**，不必重启 |
  | **模板** `templates/desktop.html` | **内存缓存**（`auto_reload=False`） | 改版本号**不重启不生效** |
- **但仍不重启也可见**：静态响应带 `Cache-Control: no-cache` + `ETag`，浏览器每次会发起校验（条件请求），内容一变即返回新文件 ⇒ **显示层不重启也能拿到新 JS**
- **解决/规避**：改静态文件 → 可直接刷新验证；改模板 → 必须重启。**两手准备**：既升 `?v=` 版本号（供重启后彻底生效），又依靠 ETag 让当下也可见
- ⚠️ 别把「重启」当成**唯一手段**（能免则免，减少对正在运行服务的扰动）；也别指望改模板**即时生效**

### [2026-09-30] 新建的笔记必然排在队列最后
- **问题**：写完一条新笔记，要往下翻到列表最底部才能看到它
- **原因**：后端 `list_notes` 排序是 `状态分组 → position → id`，而新建笔记 `position = MAX+1`（`next_position()`）→ **必然排在末尾**；前端又完全没有排序控件
- **解决/规避**：前端加**排序切换**（🕒最新在前默认 / 🕓最早在前 / 📋队列顺序），按 `created_at` 在**状态分组内部**排序（同秒用 `id` 兜底）
- ⚠️ **不要把排序改到后端 SQL**：`/api/notes` 与 `/api/auto/notes`（AutoX.js 按 `position` 自动发布）**都依赖原序**，动后端会静默改变自动发布顺序
- ⚠️ 三种排序**都要保留状态分组**（待发布→草稿→已发布），否则会破坏「已发布沉底」的原语义

### [2026-09-30] 预览把正文截断 / 只显示封面 / 封面被裁
- **问题**：预览里正文只显示开头几行；配图几乎看不到；封面上下被切掉
- **原因**：三个独立成因 —— ① `.preview-body` 带 `max-height:160px; overflow:hidden`；② 预览只渲染 `coverFiles[0]`，**其余图完全不渲染**；③ `.preview-cover` 用 `padding-bottom:100%`（1:1）配 `background-size:cover`，把 1080×1440（3:4）的封面上下裁掉
- **解决/规避**：① 去掉 `max-height/overflow`，卡片随内容自适应；② 全部配图按位置渲染；③ 封面比例改 `133.33%`；④ 配图 `img{width:100%;height:auto}` 等比缩放不溢出

### [2026-09-30] 图位标记 `[[图N]]` 会漏进发布文案
- **问题**：正文里写 `[[图2]]` 做图文混排后，手机端「复制文案」会把 `[[图2]]` 一起复制，粘到小红书里出现这串标记
- **原因**：图位标记是**内部排版语法**，但复制/显示/字数统计直接用了原始 `body`
- **解决/规避**：所有出站路径统一先 `stripImgSlots()` 剥离 —— 手机端 `copyNote`/`copyItem`/卡片显示、桌面端字数统计，**一处都不能漏**
- ⚠️ 另一个隐蔽点：桌面列表的「N 字」若按原始 `body` 统计，标记会被算进字数

### [2026-09-30] 同一函数在桌面/手机各有一份 → 必然漂移
- **问题**：`sortNotes()` 与 `stripImgSlots()` 分别在 `static/app.js` 和 `static/mobile.js` 各写了一份
- **原因**：两端是独立文件、无共享模块（刻意保持「无构建、无 CDN」）
- **解决/规避**：回归测试**不做「重写副本」**，而是**从两个源文件里各抽取真实函数体**跑同一批用例，并加**双端一致性断言**（排序 48 组矩阵 / 图位 14 组）——只改一端立刻红
- 断言见 `scripts/test_queue_sort.js`、`scripts/test_img_slots.js`

### [2026-09-06] `run.bat` / `start.bat` 用裸 `python` 会闪退
- **问题**：双击 `run.bat`，黑窗一闪就没了，网页打不开
- **原因**：PATH 里的 `python` 是 **3.13.x**，**没装 Flask** → `ModuleNotFoundError: No module named 'flask'` → 进程立刻退出
- **解决/规避**：`run.bat` 改为**自动挑选**解释器（先试 `py -3.11`，再试 `C:\Users\Dancing\AppData\Local\Programs\Python\Python311\python.exe`），都找不到就打印安装指引并 `exit /b 1`；`start.bat` 改用 `py -3.11 app.py`
- 一般化：**凡是"一键启动"，都要显式绑定解释器**，别赌 PATH（同族问题见 MEMORY-PITFALLS #10）

### [2026-09-30] 改文档/静态文件时 `Path.write_text()` 把 LF 全改成 CRLF
- **问题**：编辑后 `git diff` 显示**整个文件都变了**，看不出真实改动
- **原因**：Windows 上 Python `Path.write_text()` 默认按文本模式写，把 LF 统一替换成 CRLF；而这些文件在 git 里是 LF
- **解决/规避**：改完 `p.write_bytes(b.replace(b'\r\n', b'\n'))` 还原；**或用 Edit 工具直接改**（保留原行尾）。注意：**本来就是 CRLF 的文件不要乱转**
- 判据：`open(p,'rb').read().count(b'\r\n')` 对比改动前后

### [2026-08-21] 手机「🐟复制宝贝文案」把内部 purpose 字段拼进文案
- **问题**：复制宝贝文案粘贴后，原文结尾多一行 `purpose:idlefish`
- **原因**：`static/mobile.js` `copyItem()` 把 `meta` 所有键值都当「宝贝字段」拼进文案，而 `meta.purpose`（用途标记：xhs/idlefish/common）是**内部字段**（用于平台筛选），不是闲鱼宝贝字段
- **解决/规避**：复制时过滤掉内部 `k === 'purpose'`，只拼标题+正文+实际宝贝字段

### [2026-08-21] Flask 对模板有内存缓存，模板改动必须重启服务
- **问题**：改了 `desktop.html` 加了新筛选项，浏览器刷新多次仍看不到
- **原因**：非 debug 模式 Jinja `auto_reload=False`，模板编译一次后在内存缓存，旧模板持续吐给前端；而**静态文件**（style.css/app.js）每次从磁盘读，改完刷新即生效——两者行为不同，容易误判「没改上」
- **解决/规避**：改模板后要**重启服务**（杀 `python app.py` 进程再拉起）；改静态文件则不用。浏览器侧用 `?v=` 版本号强制重拉静态资源
- **判别方法**：`curl -s http://127.0.0.1:8800/app` 需要带登录 cookie，否则 302 到登录页抓不到真实 HTML，别用空 curl 的 grep 结果判断页面新旧

### [2026-08-21] 桌面队列复用筛选容器类导致两组 chips 可能误绑
- **问题**：队列头部原本只有状态筛选（全部/待发布/草稿/已发布），新增用途筛选（所有/小红书/闲鱼/通用）时若沿用 `.list-filters .chip` 全量选择器，两组 chips 会互相误绑、点错分类
- **原因**：同页面两个 `.list-filters` 容器，通用 `.chip` 绑定选择器会同时命中两组
- **解决/规避**：`static/app.js` 绑定区分 `[data-filter]`（状态）和 `[data-pfilter]`（用途）两个独立属性选择器；HTML 两组分别挂对应 data 属性。参见手机端 `.m-filters` 复用坑（v1.2.0）

### [2026-08-14] Windows curl 中文 JSON 返回 400
- **问题**：用 curl `-d '{"title":"中文"}'` 创建笔记报 400 Bad Request
- **原因**：Windows Git Bash 下命令行中的中文 JSON 被 shell 编码破坏，Flask 解析失败
- **解决/规避**：改用 `--data-binary @file.json`（JSON 写入 UTF-8 文件），或直接用 `import_note.py`

### [2026-08-14] 产线稿子标签抓空
- **问题**：导入脚本标签为空
- **原因**：标签行(`#打工人 #AI工具...`)在正文的 `---` 分隔之后，不在正文里；且正则 `^[#＃]` 会误匹配 markdown H1 标题行
- **解决/规避**：标签改为在**全文** hunt，且用 `^[#＃]\S+(?:\s+[#＃]\S+)+$`（要求一行全是 #tag 才认）

### [2026-08-14] 正文开头混入 H1 标题
- **问题**：导入后正文含 `# 🤩标题` 行
- **原因**：frontmatter 去掉后正文以空行开头，`while` 循环没跳过空行，导致 H1 没被剔除
- **解决/规避**：循环条件加 `not body_lines[0].strip()`（先跳空行再跳 H1）

### [2026-08-14] 产线图片引用的 `|500` 尺寸后缀

### [2026-08-14] AutoX.js 选图/按钮依赖小红书 UI 版本
- **问题**：小红书改版会导致选择器失效
- **原因**：无障碍自动化基于文案/控件 id，UI 变动即失效
- **解决/规避**：脚本内做多文案候选 `clickText(["相册","图片",...])`，并留坐标兜底；真机 DRY_RUN 后按日志微调

### [2026-08-14] 手机浏览器批量下载被拦截/弹窗闪烁
- **问题**：点「下载全部图」一次触 3 次下载，页面快速闪过多个下载界面、漏图
- **原因**：手机浏览器安全机制——单个用户手势只允许触发一次下载，后续自动下载被拦截或弹窗堆叠
- **解决/规避**：改为「逐张确认」——每张由用户亲手点「保存此图」触发（新鲜手势），点完按钮变「下一张」，全程用户控制节奏，绝不自动跳

### [2026-08-14] 手机浏览器缓存旧 JS，改了没变化
- **问题**：用户改完 mobile.js 后手机端仍显示旧行为（「没变化」）
- **原因**：手机浏览器强缓存静态 JS，旧逻辑还在跑
- **解决/规避**：模板引用加版本号 `?v=20260814-3`，URL 变化即重新拉取；并引导用户强制刷新

### [2026-08-14] AI产线图「看着像重复」
- **问题**：用户以为一篇笔记的 3 张图有重复（保存时提示像一样）
- **原因**：AI 生成的插图风格统一、主题相近，视觉上像同一张，但 MD5/像素/dHash 三重比对均不同
- **解决/规避**：非 bug。下载文件名只有尾号不同易误判，可改名区分或换差异大的图

### [2026-08-21] 手机端 `.m-filters` 选择器会同时选中平台筛选 chips
- **问题**：状态筛选绑定 `document.querySelectorAll('.m-filters .chip')`，平台组父容器也带 `.m-filters` 类 → 平台 chips 被状态 handler 误绑，点平台出怪
- **原因**：新增平台筛选时复用了 `.m-filters` 容器类
- **解决/规避**：状态组容器加独立 `id="mStatusFilters"`，绑定限定 `#mStatusFilters .chip`；平台组用 `#mPlatFilters .chip`

### [2026-08-21] 闲鱼与小红书共用队列，需用途标记防点混
- **问题**：同一队列同时发小红书+闲鱼，全默认「通用」时两个发布按钮都在，易误点
- **原因**：无平台维度区分，靠人记
- **解决/规避**：加 `meta.purpose`（xhs/idlefish/common）；桌面徽标、手机端平台筛选、按钮按用途收敛（闲鱼稿只显示宝贝按钮、小红书稿只显示复制文案）

## 已知风险（非 bug，业务约束）
- 小红书图片只能「先存相册再选」，浏览器无法多图粘进小红书
- 自动化有设备指纹识别/封号风险，建议低频率 + 存草稿
- iOS 无无障碍自动化，自动填充仅安卓
